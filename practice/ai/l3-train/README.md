## 怎么跑

```powershell
cd practice/ai/l3-train
uv run --project ../l2-nanogpt python train_base.py   # 块 1：默认设置两次同 seed（判据 A–B）
uv run --project ../l2-nanogpt python train_det.py    # 块 2+3：确定性开关下 A–B（两次同 seed）+ C（3 个 seed）
uv run --project ../l2-nanogpt python train_det.py repeat   # 只跑块 2（约 70 s）
uv run --project ../l2-nanogpt python train_det.py noise    # 只跑块 3（约 105 s）
uv run --project ../l2-nanogpt python lr_sweep.py          # 关 1：原文五档（约 3 分钟）
uv run --project ../l2-nanogpt python lr_sweep.py ext      # 关 1：扩展档 1e-7/1e-6/3e-2/1e-1/1.0
uv run --project ../l2-nanogpt python lr_sweep.py tiny     # 关 1：1e-8（查「不动」是否存在）
uv run --project ../l2-nanogpt python lr_sweep.py read      # 只读 curves/lr-*.csv 复算总表（不用 GPU）
uv run --project ../l2-nanogpt python warmup_sweep.py       # 关 2 base 组：lr=1e-3 · warmup 0/100/500
uv run --project ../l2-nanogpt python warmup_sweep.py hot   # 关 2 机制对照：lr=1e-1 同样三档
uv run --project ../l2-nanogpt python warmup_sweep.py read  # 只读 curves/wu-*.csv 复算两组
uv run --project ../l2-nanogpt python overfit.py            # 关 3：基线 + wd 0.1 干预（各约 60 s）
uv run --project ../l2-nanogpt python overfit.py probe      # 关 3 探速：100 KB 跑 2000 步看走势
uv run --project ../l2-nanogpt python batch_sweep.py        # 关 4 ①：batch 8/32/128（lr 线性缩放）
uv run --project ../l2-nanogpt python batch_sweep.py fixed  # 关 4 ②：同 lr 1e-3 换 batch 8 vs 128
uv run --project ../l2-nanogpt python batch_sweep.py read   # 只读 CSV 复算两组终值
uv run --project ../l2-nanogpt ruff check .
```

⚠️ 为什么带 `--project ../l2-nanogpt`：本目录**没有自己的 `pyproject.toml`**，直接借用 L2 的虚拟环境
（同一台机器、同一套 torch cu128、同一份语料缓存 `../l2-nanogpt/data/`）。再建一个工程要多拷约 3 GB，
而本关的判据恰恰要求「模型规模 / 步数 / 语料与 L2 关 4 完全一致」—— 复用环境本身就是判据的一部分。

## 实测数字（关卡 0 · 块 3：3 个 seed 的噪声带）

| seed | val CE | train CE | 耗时 | 峰值 |
|---|---|---|---|---|
| 1337 | **1.801705** | 1.598846 | 35.5 s | 0.368 GiB |
| 2024 | **1.782145** | 1.610352 | 34.1 s | 0.368 GiB |
| 7 | **1.789220** | 1.632307 | 33.6 s | 0.368 GiB |
| **极差** | **0.019560** | 0.033461 | — | — |

**噪声带门限 = 0.019560 nats/char**（约 1.09 % of 1.80）⇒ 关 1–4 里任何「变好 / 变坏」必须超过 **0.0196** 才算信号，小于它一律记「在 seed 噪声内」。

两条附带证据：

- seed 1337 这一次是**第三个独立进程**跑出来的 **1.801705**，与块 2 `det-same-1` 的 **1.801704860** 逐位相同 ⇒ 确定性不是只在同一进程内有效（顺带省了一次交叉验证的成本）。
- 三个 seed 的峰值显存都是 **0.368 GiB** ⇒ 显存不吃 seed，可当稳定性检查。

曲线落 `curves/<前缀>-same-{1,2}.csv`（四列：`step,train_step_ce,train_eval_ce,val_eval_ce`）。
前缀 `raw-` = 默认设置，`det-` = 确定性模式，**两块必须分前缀**（见下方踩坑）。
**不落 `runs/`**：根 `.gitignore` 忽略 `runs/`，而曲线是判据证据、要入库。

### 口径（改必须写理由）

| 项 | 口径 |
|---|---|
| 随机性入口 | 一次 run 的全部随机性只由 `train_once(seed)` 的 `seed` 派生：模型初始化、训练采样、评估采样三个流分开 |
| `manual_seed` 的位置 | 必须写在 `CharGPT(...)` **之前**；写在之后 = 权重吃上一轮的残留状态，第 1 步就分叉 |
| 评估流 | `torch.Generator().manual_seed(seed + 1)` —— 同一份权重 + 同一个评估流，val CE 才可能逐位相同 |
| 逐步 CE | 取**该步那个 batch 的 loss**（不是评估估计值）；单 batch 噪声大，但两次之间是共模的 |
| A 的阈值 | `STEP_TOL = 1e-9`：float32 的 loss 本身是 1e-7 量级，1e-9 已比末位更紧；卡严格 0 会把同一路径的末位 rounding 判红 |
| 计时起点 | `t0` 放在优化器之后、循环之前 —— 只量训练循环，才与 L2 关 4 的 45.7 s 可比 |
| 曲线文件名 | `judge_repeat(tag_prefix)` 必须带前缀：`raw-` / `det-`，否则后跑的覆盖先跑的证据 |
| **确定性模式为默认** | 2026-11-26 定：**关 1–4 的所有对照一律在 `train_det.py` 那套开关下跑**。理由 = 默认设置同 seed 重跑就差 6.4e-3，而关 1 相邻 lr 档位的差异可能只有 1e-2 量级，不可复现的噪声会把判据淹掉；代价只有显存 +14.3 %（耗时测不出） |
| **噪声带取法** | 3 个 seed（**1337 / 2024 / 7**）在跑之前写死，极差 = 门限；不按结果挑 seed。带子里只含「seed 噪声」，「同 seed 重跑噪声」在确定性模式下 = 0（块 2 已证） |

## 实测数字（关卡 1 · lr 扫描 · 2026-11-26）

文件：`lr_sweep.py`（确定性开关 + `train_once(seed, lr)`；`report` / `classify` 由 AI 写；`train_once` 只加了 `lr` 参数）。
口径：起点 val CE **4.3175**、噪声带 **0.019560**、11 档全部 2000 步、seed 1337、峰值显存恒 0.368 GiB。

| lr | 终值 val CE | 前 100 步峰值 | 首个 NaN/inf | 形态 |
|---|---|---|---|---|
| **1e-8** | **4.3042** | 4.3405 | 无 | **不动** |
| 1e-7 | 4.1874 | 4.3384 | 无 | 稳降 |
| 1e-6 | 3.3370 | 4.3329 | 无 | 稳降 |
| 1e-5 | 2.5432 | 4.3257 | 无 | 稳降 |
| 1e-4 | 2.1786 | 4.3257 | 无 | 稳降 |
| 3e-4 | 1.8017 | 4.3257 | 无 | 稳降 |
| **1e-3** | **1.6113** | 4.3257 | 无 | 稳降 ← **最优** |
| 1e-2 | 1.6843 | 4.3257 | 无 | 稳降 |
| 3e-2 | 2.9011 | 4.6466 | 无 | 稳降 |
| 1e-1 | 3.3488 | **12.6887** | 无 | 稳降（早期炸过又爬回） |
| **1.0** | **91.2485** | **477.2376** | **无** | **发散**（首个 CE>10 在**第 2 步**，末 200 步均值 118.99） |

**结论（判据 ②）**：稳值区间 **[1e-7, 1e-1]** · 最优 **lr = 1e-3（1.611282）** ·
**有效区间（val CE < bigram 基线 2.4819）= [1e-4, 1e-2]**。

### 两处如实记（不是凑绿）

1. **判据 ① 的三种形态在原文五档内凑不齐**：`1e-5 / 1e-4 / 3e-4 / 1e-3 / 1e-2` 实测**全是稳降**（1e-5 都降了 1.77 nats）。
   补 6 档后（1e-8 不动、1.0 发散）形态才齐 ⇒ 记为**口径偏离**：形态齐来自扩展档位，不是原文那五个。
   原因：0.83 M 参数 + AdamW 的稳值区间比原文预期**宽约两个数量级**（下界要到 1e-8 才「不动」）。
2. **没有 NaN**：判据原文写「如 lr=1e-2 第几步起 NaN」，但本模型到 lr=1.0 也没 NaN，表现是**CE 爆到 91.25（峰值 477.24）**。
   ⇒ 「发散」的落地定义必须是「终值比不训练更差，或 CE 整体上升，或非有限」，**不能只认 NaN**。

### 发散长什么样（数字）

- `lr=1.0`：第 **2** 步 CE 就 > 10；val CE 曲线 `0:4.32 → 100:216.97 → 200:245.07 → 300:135.98 → … → 2000:91.25`；
  全程**没有非有限值**，末 200 步均值仍 118.99 ⇒ 权重被推到 logits 极端的区域后，靠 `grad_clip=1.0` 卡在里面来回撞。
- `lr=1e-1`：前 100 步峰值 **12.69**（早期也炸过一次），但爬回到 3.3488 —— 说明「一开始炸」与「最终发散」是两件事，必须分开看（前者看峰值，后者看终值 + 趋势）。
- `lr=3e-2`：不炸，但 2.9011 比 1e-2 差 1.2 ⇒ **上界在 1e-2 与 3e-2 之间**，越过就迅速退化。

### 分类器踩的坑（已修）

第一版 `classify` 只按「末 200 步均值在上升」判发散 ⇒ `lr=1.0` 因为爆炸后一路在 100~250 震荡、末段还往下掉，被误判成**「不动」**（91.25 ≥ 起点 − 噪声带）。
修法：发散的第一条改成「**终值比不训练还差**（`val_ce > START_CE`）」，爆炸先判。⇒ 判据里「比起点差」必须是第一个条件，不能排在「趋势」后面。

## 实测数字（关卡 2 · warmup · 2026-11-26）

文件：`warmup_sweep.py`；`train_once` 新增 `warmup: int = 0`（前 `warmup` 步 `lr_scale = (step+1)/warmup`，之后恒 1）。
口径：三档 warmup `0 / 100 / 500`，各 2000 步，seed 1337，确定性模式，峰值显存恒 0.368 GiB。

### base 组（lr = 1e-3，关 1 的最优稳值）—— 判据 ①

| warmup | 终值 val CE | 前 200 步峰值 | 峰值出现步 |
|---|---|---|---|
| 0 | 1.611282 | 4.3257 | 1 |
| 100 | **1.607632** | 4.3257 | 1 |
| 500 | 1.621968 | 4.3270 | 2 |

**三档终值极差 0.014336 ≤ 噪声带 0.019560 ⇒ 记「本模型不需要 warmup」**（判据 ② 允许的第一种结论）。
三档峰值极差只有 **0.001299** —— 稳值档上 warmup 无从发力，因为它本来就不会把权重推坏。

### hot 组（lr = 1e-1，关 1 里会早炸的那档）—— 判据 ② 的机制证据

| warmup | 终值 val CE | 前 200 步峰值 | 峰值出现步 |
|---|---|---|---|
| 0 | 3.348767 | **12.6887** | 6 |
| 100 | 3.359062 | **4.3257** | 1 |
| 500 | **3.283613** | **4.3257** | 1 |

两句话把机制说清（都是数字）：

1. **warmup 确实防住了早炸**：前 200 步峰值 **12.6887 → 4.3257**（压低 **8.3630**，且峰值不再出现在第 6 步——因为第 1 步的 lr 只有 `lr/warmup`）。这是「**早期大 lr 把权重推坏**」那一半。
2. **warmup 救不了收敛**：三档终值 3.2836 / 3.3488 / 3.3591，极差 0.0754，**全都在 3.3 附近**，远差于 1e-3 的 1.6113。说明 lr=1e-1 本身太大，warmup 只能把「前几步不炸」买回来，买不回「好终值」。这是「**不是后期收敛慢**」那一半。

⚠️ 这条对照是**追加的**（判据原文只要求 base 三档）。理由：稳值档上三档完全没差别，若只跑 base，「warmup 解决早期推坏」这句话就没有任何数字支撑 —— 结论正确但没被验证过。

| 耗时 / 峰值 | 61.8 s（含 3500 步 + 36 次评估）· **0.369 GiB** |

### 判据 ②（干预：weight decay 0.01 → 0.1）

| 项 | 基线 wd 0.01 | 干预 wd 0.1 | 差 |
|---|---|---|---|
| 到 0.5 的步数 | 1500 | **1700** | **+200（+13.3%）** |
| 拐点 | step 700 · val 1.6689 | step 700 · val **1.6586** | 位置**不变**，值低 0.0103（< 噪声带 0.0196） |
| 末步 val | step 3500 · 4.6881 | step 3700 · **4.4441** | **低 0.2440**（噪声带的 12 倍） |
| 升幅 | +3.0192 | +2.7855 | 小 0.23 |

**结论：干预有效但很弱** —— 它把「背下来」的速度拖慢 200 步、把过拟合的上限压低 0.24，但**没能阻止过拟合**（val 仍然升到 4.44，比随机初始化差）。要真压住，得靠早停（step 700 就停）或更多数据，不是靠 0.1 的 wd。

## 实测数字（关卡 4 · batch · 2026-11-26）

文件：`batch_sweep.py`；锚点 = 关 1 实测最优（batch 64 + lr 1e-3）⇒ `lr(b) = 1e-3 × b/64`。
语料回到全量 1.1 MB、seed 1337、2000 步、评估口径固定 20×64×128（不随训练 batch 变）。

### 判据 ①（lr 按 batch 线性缩放）

| batch | lr | 终值 val CE | train CE | ms/步 | 峰值 GiB | **该档看的 token 数** |
|---|---|---|---|---|---|---|
| 8 | 1.25e-4 | **2.384780** | 2.3485 | 16.9 | 0.135 | 2.05 M |
| 32 | 5e-4 | **1.733131** | 1.5410 | 16.3 | 0.222 | 8.19 M |
| 128 | 2e-3 | **1.587324** | 1.2435 | 28.8 | 0.664 | **32.8 M** |

最好的一档是 batch 128（1.5873），三档极差 **0.797456**。

⚠️ **这里有个混入变量，必须写明**：判据原文是「各 2000 步」，但同样 2000 步、每步 token 数差 **16 倍** ⇒ batch 128 实际看了 **32.8 M** token，batch 8 只看了 **2.05 M**。「batch 128 更好」里有一部分是**数据看得多**，不纯是 batch 的功劳。要拆开得让 batch 8 跑到 16000 步（约 4.4 分钟），本关未做（判据没要求等 token），如实记在此。

### 判据 ②（同 lr 1e-3，只换 batch）

| batch | lr | 终值 val CE | ms/步 | 峰值 GiB | 与缩放组比 |
|---|---|---|---|---|---|
| 8 | 1e-3（缩放该给 1.25e-4，**8 倍**） | **1.838578** | 16.4 | 0.135 | 比缩放组好 **0.546** |
| 128 | 1e-3（缩放该给 2e-3，**一半**） | **1.593847** | 28.9 | 0.664 | 比缩放组差 **0.0065**（基本无差） |

**耦合结论（两个数字说清）**：

1. **小 batch 对 lr 极敏感**：batch 8 上把 lr 从 1.25e-4 提到 1e-3（8 倍），val 从 2.3848 降到 1.8386（**改善 0.546**）⇒ 线性缩放给小 batch 的 lr **明显偏小**，它在 2000 步里根本没走到位。
2. **大 batch 对 lr 不敏感**：batch 128 上把 lr 砍一半（2e-3 → 1e-3），val 只差 **0.0065** ⇒ 同样的「梯度噪声/步」下，大 batch 的容忍区间宽得多。
3. ⇒ 「大 batch 不缩 lr 会怎样」= 这条实验里没炸（1e-3 是它缩放值的一半，属于**更保守**的方向）；真正的危险方向是「小 batch 配大 lr」，本关的 batch 8 + 1e-3 已经是 8 倍缩放值仍稳（因为 8 倍后也只有 1e-3，离关 1 的上界 1e-2 还远）。

## 踩过的坑

| 坑 | 现象 / 怎么抓 |
|---|---|
| **曲线文件名不带模式前缀 = 自己覆盖自己的证据** | 块 1 跑完 `same-1.csv` / `same-2.csv`，块 2 一跑同名的把块 1 覆盖。⇒ `judge_repeat(tag_prefix)` 强制前缀，重跑块 1 才把 `raw-` 证据重新生成 |
| **首跑耗时不是稳定量** | 同一脚本同一路径：43.7 / 30.4 / 35.3 / 33.4 / 47.0 / 49.9 s。首跑要付 kernel 预热与时钟爬升的账 ⇒ **耗时对照必须同批同条件跑，不能跨批比**（本关「确定性模式的耗时代价」因此判为测不出来） |
| **`CharGPT` 没有 `block_size` 参数** | 签名是 `(vocab_size, c, n_layer)`；位置表长度由 `model.py` 的常量 `BLOCK` 决定。写成 `block_size=BLOCK` 直接 `TypeError` |
| **`torch.optim.AdamW(...)` 不接返回值** | 优化器对象丢了，循环里 `opt.step()` 变成 `NameError`；ruff 的 `F841` 抓不到（它没赋值）—— 靠 `F821 Undefined name opt` |
| **宏观上看不出分叉** | 终端打印 4 位小数时，前 600 步两组曲线**完全一样**；必须从 CSV 按 1e-9 逐行比，才看到第 40 步就已经差 1e-6 |
| **「发散」不能只认 NaN** | `lr=1.0` 全程没有 inf/NaN，CE 却到 91.25（峰值 477.24）；而 `lr=1e-1` 前 100 步峰值 12.69 却爬回 3.35 ⇒ 峰值（早炸）与终值（真发散）是两件事 |
| **分类器的条件顺序会决定结论** | 第一版先判「趋势上升」，`lr=1.0` 的终值 91.25 被归成「不动」。⇒ 「终值比不训练还差」必须是发散的第一条 |
| **`⇒`（U+21D2）在 GBK 控制台直接炸** | `UnicodeEncodeError: 'gbk' codec can't encode character '\u21d2'`，与 `✓` / `−` / `³` 同一族。判据 `print` 里一律 ASCII（`->`） |
| **同一天同一脚本耗时从 34 s 涨到 73 s** | 关 1 单档 34–38 s，关 2 单档 70–74 s（同 lr、同步数、同显存 0.368 GiB）。⇒ 机器热状态/后台负载会整倍改变耗时，**耗时不跨批比**这条再次坐实 |
| **「各 2000 步」不等于「等量数据」** | 关 4 ① 三档每步 token 数差 **16 倍**（8×128 vs 128×128）⇒ batch 128 看了 32.8 M token、batch 8 只看 2.05 M。「大 batch 更好」里混着「数据更多」，判据没要求等 token，但结论必须带这句 |
| **小语料的词表会变** | 100 KB 切片词表 **61**（全量是 65）⇒ 词表维变小、CE 的基准也变，**不能拿关 3 的 CE 和关 1/2 直接比** |
| **小语料让评估从「抽样」变「近似全量」** | val 只有 10,000 字符（窗口起点约 9,871 个），而 `estimate_ce` 抽 20×64 = 1280 个窗口 ⇒ 覆盖整段 16 遍。误差更小，但不是「独立样本」，跨关比 CE 会张冠李戴 |
