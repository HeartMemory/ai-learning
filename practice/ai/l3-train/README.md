uv run --project ../l2-nanogpt python train_det.py    # 块 2+3：确定性开关下 A–B（两次同 seed）+ C（3 个 seed）

## 实测数字（关卡 0 · 块 1：默认设置）

| 判据 | 实测 |
|---|---|
| A 逐步一致（最大绝对差 < 1e-9） | **1.944e-02**（最大差在 step 1236）**NG** |
| B 终值一致（val CE 差 == 0） | **6.397e-03**（1.806031 vs 1.799635）**NG** |
| 首次分叉 | **step 40**，差约 **1e-06**（CSV 精度上限） |
| 有差步数 | **1371 / 2000**（前约 600 步在 6 位小数上一致） |
| 耗时 | **43.7 s / 30.4 s** · 峰值 **0.322 / 0.322 GiB** |
| 同配置重跑的第二组（另一天同一小时） | 1.800093 / 1.802309（差 2.216e-03）· 最大逐步差 2.592e-02 |

**读法**：前 40 步一致 ⇒ 初始化、数据流、前向都是确定的；第 40 步起 1e-6 量级差 ⇒ 反向的**梯度**已不同；
放大到 1.9e-02 ⇒ 训练动力学是混沌式的（1e-6 的扰动 1200 步放大 4 个数量级）。
⇒ **判据必须比「逐步」**：只看终值 6e-03 会误以为是评估噪声。

## 实测数字（关卡 0 · 块 2：确定性模式）

开关：`CUBLAS_WORKSPACE_CONFIG=:4096:8`（写在 `import torch` 之前）+ `torch.use_deterministic_algorithms(True)`
+ `cudnn.benchmark=False` + `cudnn.deterministic=True`。

| 判据 | 实测 |
|---|---|
| A 逐步一致 | **0.000e+00** · 有差步数 **0 / 2000** **OK** |
| B 终值一致 | **1.801704860 vs 1.801704860**，差 **0.000e+00** **OK** |
| 耗时 | **35.3 s / 33.4 s**（同一台机器首跑在 30–50 s 之间波动 ⇒ **耗时代价测不出来**） |
| 峰值显存 | **0.368 GiB**（默认设置 **0.322 GiB**，**+46 MiB = +14.3%**，这条稳定可测） |
| 数值是否变化 | 变：val CE 1.8017（确定性）vs 1.8001 / 1.8023 / 1.8060 / 1.7996（默认四条各不相同）—— 确定性算子换了累加顺序，**开确定性本身会改数值，但之后可复现** |

**结论**：本机这条路径**默认不可复现**，开确定性后**严格 0**；代价可测的只有显存（+14.3%），耗时淹没在噪声里。

## 实测数字（关卡 0 · 块 3：3 个 seed 的噪声带）

| seed | val CE | train CE | 耗时 | 峰值 |
|---|---|---|---|---|
| 1337 | **1.801705** | 1.598846 | 35.5 s | 0.368 GiB |
| 2024 | **1.782145** | 1.610352 | 34.1 s | 0.368 GiB |
| 7 | **1.789220** | 1.632307 | 33.6 s | 0.368 GiB |
| **极差** | **0.019560** | 0.033461 | — | — |

**噪声带门限 = 0.019560 nats/char**（约 1.09 % of 1.80）⇒ 关 1–4 里任何「变好 / 变坏」必须超过 **0.0196** 才算信号，小于它一律记「在 seed 噪声内」。

两条附带证据：

- seed 1337 这一次是**第三个独立进程**跑出来的 **1.801705**，与块 2 `det-same-1` 的 **1.801704860** 逐位相同 ⇒ 确定性不是只在同一进程内有效（顺带省了一次交叉验证的成本）。
- 三个 seed 的峰值显存都是 **0.368 GiB** ⇒ 显存不吃 seed，可当稳定性检查。

曲线落 `curves/<前缀>-same-{1,2}.csv`（四列：`step,train_step_ce,train_eval_ce,val_eval_ce`）。
前缀 `raw-` = 默认设置，`det-` = 确定性模式，**两块必须分前缀**（见下方踩坑）。
**不落 `runs/`**：根 `.gitignore` 忽略 `runs/`，而曲线是判据证据、要入库。

### 口径（改必须写理由）

| 项 | 口径 |
|---|---|
| 随机性入口 | 一次 run 的全部随机性只由 `train_once(seed)` 的 `seed` 派生：模型初始化、训练采样、评估采样三个流分开 |
| `manual_seed` 的位置 | 必须写在 `CharGPT(...)` **之前**；写在之后 = 权重吃上一轮的残留状态，第 1 步就分叉 |
| 评估流 | `torch.Generator().manual_seed(seed + 1)` —— 同一份权重 + 同一个评估流，val CE 才可能逐位相同 |
| 逐步 CE | 取**该步那个 batch 的 loss**（不是评估估计值）；单 batch 噪声大，但两次之间是共模的 |
| A 的阈值 | `STEP_TOL = 1e-9`：float32 的 loss 本身是 1e-7 量级，1e-9 已比末位更紧；卡严格 0 会把同一路径的末位 rounding 判红 |
| 计时起点 | `t0` 放在优化器之后、循环之前 —— 只量训练循环，才与 L2 关 4 的 45.7 s 可比 |
| 曲线文件名 | `judge_repeat(tag_prefix)` 必须带前缀：`raw-` / `det-`，否则后跑的覆盖先跑的证据 |
| **确定性模式为默认** | 2026-11-26 定：**关 1–4 的所有对照一律在 `train_det.py` 那套开关下跑**。理由 = 默认设置同 seed 重跑就差 6.4e-3，而关 1 相邻 lr 档位的差异可能只有 1e-2 量级，不可复现的噪声会把判据淹掉；代价只有显存 +14.3 %（耗时测不出） |
| **噪声带取法** | 3 个 seed（**1337 / 2024 / 7**）在跑之前写死，极差 = 门限；不按结果挑 seed。带子里只含「seed 噪声」，「同 seed 重跑噪声」在确定性模式下 = 0（块 2 已证） |

## 文档依据（2026-11-26 查证 · 三条来源交叉）

| 来源 | 确认了什么 |
|---|---|
| PyTorch `notes/randomness.html`（Reproducibility） | 完全可复现**不跨版本 / 平台 / CPU-GPU 保证**；`manual_seed` 只固定**随机数序列**，不固定**浮点累加顺序**；`cudnn.benchmark=True` 会因 autotune 选到不同算法；`use_deterministic_algorithms(True)` 遇非确定算子直接抛错，且 CUDA + cuBLAS 场景需设 `CUBLAS_WORKSPACE_CONFIG` |
| PyTorch 论坛 `Does scaled_dot_product_attention's backward support reproduce`（2025-12） | SDPA 在 CUDA 上可能选到非确定算法以换性能 |
| PyTorch 2.13 发布博客（FlexAttention deterministic backward 一节） | flash 后端的反向**默认用原子操作累加 dQ** ⇒ 同一输入重复执行可能得到略有不同的梯度 |

## 踩过的坑

| 坑 | 现象 / 怎么抓 |
|---|---|
| **曲线文件名不带模式前缀 = 自己覆盖自己的证据** | 块 1 跑完 `same-1.csv` / `same-2.csv`，块 2 一跑同名的把块 1 覆盖。⇒ `judge_repeat(tag_prefix)` 强制前缀，重跑块 1 才把 `raw-` 证据重新生成 |
| **首跑耗时不是稳定量** | 同一脚本同一路径：43.7 / 30.4 / 35.3 / 33.4 / 47.0 / 49.9 s。首跑要付 kernel 预热与时钟爬升的账 ⇒ **耗时对照必须同批同条件跑，不能跨批比**（本关「确定性模式的耗时代价」因此判为测不出来） |
| **`CharGPT` 没有 `block_size` 参数** | 签名是 `(vocab_size, c, n_layer)`；位置表长度由 `model.py` 的常量 `BLOCK` 决定。写成 `block_size=BLOCK` 直接 `TypeError` |
| **`torch.optim.AdamW(...)` 不接返回值** | 优化器对象丢了，循环里 `opt.step()` 变成 `NameError`；ruff 的 `F841` 抓不到（它没赋值）—— 靠 `F821 Undefined name opt` |
| **宏观上看不出分叉** | 终端打印 4 位小数时，前 600 步两组曲线**完全一样**；必须从 CSV 按 1e-9 逐行比，才看到第 40 步就已经差 1e-6 |
