# 2026-10-30（周五）· 仓库结构定稿 + S0 第 3 章可变性 + 多轮对话实战

## 三句话复盘

1. **最大收获**：**可变性的四张面孔串成了一条线** —— 默认参数（`__defaults__` 是物证）→ 函数传参（改对象 vs 重新绑定是分水岭）→ `+=`（`when possible` in-place，看类型）→ 多轮对话（`messages` 必须原地追加）。四个场景，**同一个判据**：看 `id`、看调用方手里那份数据，不看代码长什么样。
2. **最大教训**：**红波浪 ≠ 代码错**。`f.__defaults__[0]` 和 `resp.usage` 都被 Pylance 判为"可能是 None"——那是 typeshed 签名的保守估计，不是我的 bug。收窄用 `assert`。但同时要分清：`Any` / `ignore` 用在**第三方 SDK 的类型边界**上是合理妥协，用在**自己该知道的地方**就是掩盖。
3. **明天第一步**：S0 第 4 章 `dict` / `set` / `tuple` —— 为后面的 tool schema 铺路（`messages` 本身就已经是 `list[dict]` 了）。

## 今日沉淀

| 领域 | 内容 | 关键判据（可复测） |
|---|---|---|
| **可变性** | 默认参数只在 `def` 时求值一次 | `f.__defaults__` 三次调用后是 `([1, 2, 3],)`；`f(1) is f.__defaults__[0]` 为 `True` |
| **可变性** | 改对象 vs 重新绑定 | `append` 调用方可见（`id` 不变）；`nums = nums + [x]` 不可见（名字改指新对象） |
| **可变性** | `+=` 是否原地由**类型**决定 | `list` 原地（`id` 不变）；`int` / `str` / `tuple` 新建（`id` 变）；`dict` 直接不支持 |
| **多轮对话** | 模型**无状态**，上下文 = 每次把整个历史重发 | `prompt_tokens` 增量 ≈ 上一轮新增文本的 token 数 |
| **类型系统** | `X | None` 的收窄手法 | `assert x is not None` 之后检查器才认；`assert` 在 `python -O` 下会被剥掉 |
| **仓库结构** | 练习区分桶 + 年/月分层 | `practice/<桶>/<年>/<月>/<日期-主题>/`；13 个文件全部识别为 rename（0 行改动） |

| 指标 | 数值 |
|---|---|
| 模型 | `deepseek-flash`（BASE_URL = `https://api.deepseek.com`） |
| 调用次数 | **3 次**（同一进程内的三轮对话） |
| prompt_tokens | **46 / 62 / 96**（逐轮 +16 / +34） |
| completion_tokens | **32 / 78 / 36**（第 2 轮偏大 = 复述整句 + 思考模式） |
| total_tokens | **78 / 140 / 132** |
| 端到端耗时 | **1185.61 / 821.39 / 749.14 ms**（首轮含建连，故最慢） |
| 成本 | 未结算（调用量太小；S1 起按「百万 token 单价 × 实测用量」算） |

⭐ **两个可复算的判据**：

- **第 2 轮 prompt 增量 16** ≈ 上轮回答 `"2"`（1）+ 本轮问题（15）⇒ **模型确实收到了完整历史，而不是只收到新问题**
- **第 3 轮 prompt 增量 34** ≈ 上轮"复述整句"（≈20）+ 本轮问题（≈14）⇒ **增量与上一轮回答的长度成正比**，这就是"每次都重发"的直接证据
