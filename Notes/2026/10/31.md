# 2026-10-31（周六）· S0 第 5 章 async / await：让出点决定一切

## 三句话复盘

1. **最大收获**：**并发不是 `async` 给的，是 `await` 让出给的** —— 一条根串起四个证据：顺序 await **2.02 s** vs `gather` **1.00 s**；`create_task` 提交完 `done=False`（0.92 ms）而任务 0.99 ms 才开跑；不让出的 `hog()` 让整条队列空白 **50 ms**；`time.sleep` 让 `gather` 打回 **2.00 s** 而 `asyncio.to_thread` 救回 **1.00 s**。**唯一的切换点是让出点，`gather` 没有抢占权。**
2. **最大教训**：**"写了 `await`" ≠ "让出了控制权"**。`await instant()`（被 await 的协程内部无挂起）实测 `X前 → X后 → Y前 → Y后`，**完全没有交错** —— 执行点不等于让出点，要强制让一轮只能 `await asyncio.sleep(0)`。另外「红波浪 ≠ 代码错」再现一次：`gather` 运行时返回 `list`，但类型存根说 `tuple`，`-> list[str]` 被 Pylance 判错（实测 `isinstance(r, list)` 为 `True`）。
3. **明天第一步**：**周日复盘日** —— 先盲写第 5 章四张牌（`async def` 调用不执行 / 让出点 / `gather` vs `TaskGroup` / 同步阻塞毒药），再整理计基「并发与异步」30 分钟，然后周记 + Block 校准。

## 今日沉淀

| 领域 | 内容 | 关键判据（可复测） |
|---|---|---|
| **协程本体** | `async def` 调用**不执行**，只返回 `coroutine` 对象 | `type(nap("a"))` 是 `coroutine`；不 await 时退出报 `RuntimeWarning: coroutine 'nap' was never awaited` |
| **让出点** | `await` 是执行点，**也是唯一的让出点**；`gather` 只负责排队 | 8 行交替输出在 `0.78 → 0.83 ms` 内跑完 ⇒ 单次切换 ≈ **10 µs 级** |
| **让出 ≠ 结束** | 挂起的任务**还活着**，之后会被切回来；`return` / 抛异常是**散场**，循环此时才收回控制权 | 场景 B：`hog()` 从 `0.87 ms` 忙到 `50.87 ms`，期间 `D` 一步没跑（`D#0` 出现在 `50.93 ms`） |
| **两种「等」** | 就绪队列（等被调度）vs 等待队列（等外部事件就绪） | `create_task` 后 `done=False`（已入队未跑）；`await sleep(1)` 是等定时器 |
| **有 await ≠ 让出** | `await` 一个内部无挂起的协程 → **直接穿过**，不交还控制权 | 情况 1：`X前 1.06 / X后 1.08 / Y前 1.08 / Y后 1.09`（零交错）；情况 2 用 `sleep(0)`：`X前 1.13 / Y前 1.13 / X后 1.14 / Y后 1.14` ✅ |
| **并发 ≠ 并行** | 单线程协作式；同一时刻只有一个任务在跑，只对"等外部"有效 | 实验里 `threading.active_count()` = **1**；纯 CPU 忙等只是把别人饿死 |
| **`gather`** | 把协程变成 Task 排队，返回 **list（传入顺序）**；首个异常立刻抛，但**不取消**其余 | `b` 只睡 0.2 s 仍排第二；异常demo：**0.05 s** 冒 `RuntimeError`，`safe` 在 **1.00 s** 正常跑完 |
| **`TaskGroup`** | 等待发生在**退出 `async with`**；结果从各 Task `.result()` 取；出错**取消其余** + `ExceptionGroup` | 提交完 `ta 类型=Task done=False`；`b` 0.2 s / `a` 1.0 s → 总 **1.00 s** = `max(1.0, 0.2)`；出错时 `safe` 被取消 |
| **同步阻塞毒药** | `time.sleep` / `requests` 这类同步调用**占死唯一的线程**，`gather` 救不回来 | 直接 `time.sleep`：**2.00 s**（`a` 出来 `b` 才进入）；`to_thread` 版：**1.00 s**（交错） |
| **抢占 vs 协作** | 线程 = OS 强制切（睡一个线程不影响别人）；协程 = 只有代码主动让出才切（睡的是整个线程） | 同上两条耗时差 2 倍，根因就在这里 |
| **API 面** | Task 自身：`result / exception / done / cancelled / cancel / set_name / add_done_callback`；模块级：`gather / TaskGroup / wait / as_completed / timeout / wait_for / shield / to_thread` | `as_completed`：`快(0.1s)` 先出、`慢(0.3s)` 后出；`wait(timeout=0.2)` → `done=1 / pending=1` 且**不抛异常**；`exception()` 返回 `ValueError('故意失败')` 而**不抛** |
| **结构化并发** | 作用域一退出必等完 + 异常不静默丢弃 = `TaskGroup` 比 `gather` 安全的根 | 官方 Note + 独立来源（Trio 教程）一致 |
| **3.14 环境** | `get_event_loop()` 不再隐式建循环；`create_task` 返回的 Task 是**弱引用**；`gather` 无变更未弃用 | `sys.version` = `3.14.8`；`hasattr(asyncio,'TaskGroup')` / `'timeout'` 均 `True` |

- **`2.02 / 1.00` 这组比值**：`2 个 × 1 s` 串行 = 2 s，并发 = `max(1, 1)` = 1 s ⇒ **并发只在"等"上赚，赚多少取决于最慢的那个**
