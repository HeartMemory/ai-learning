## 今日沉淀

### 因果掩码为什么这么做

- 目标不是"让未来权重为 0"，而是**让未来的分数参与不了归一化**。所以 `-inf` 必须加在 **softmax 之前**：`exp(-inf) = 0`，剩下的位置重新分掉 100% 的预算，行和仍 = 1。
- 三种错法各有症状：① 乘 0 → softmax 把 0 当"分数很低"重新归一，未来照样分到权重；② softmax 后置 0 → 行和 < 1，注意力预算漏一块；③ 把未来的 `v` 置 0 → 行和仍 1，但输出被稀释（权重还在，值没了）。
- `tril(diagonal=0)` 的 `diagonal` 管的是「自己看不看自己」：`-1` ⇒ 第 0 行全 False ⇒ `softmax(全 -inf) = nan`（本机实测确实是 `nan`）；`+1` ⇒ 每行多留一个未来位（泄漏）。
- 掩码边长是 **T**（token 数），不是 d。分数 `(T,T)` 来自 `q@k.T`，点积把 d 个分量加成了一个数，d 在分数里已经消失。写成 `(T,d)` 会直接报形状错。

### 位置编码的两条通道

| | 加法（正弦 / 可学表） | 乘法（RoPE） |
|---|---|---|
| 注入点 | `x + p`，随表示进 `W_q/W_k` | `R_m q`，只作用于 q、k |
| 相对性 | 隐式，要靠 `W_q^T W_k` 凑 | 精确，`q_m·k_n` 只依赖 `n−m` |
| 是否污染 `v` | 会（`p` 加在输入上） | 不会 |
| 保长度 | 加法会改范数 | 正交 ⇒ 范数不变 |
| 工业现状 | 原版 Transformer / nanoGPT（可学表）/ BERT / ViT | LLaMA 系 |

- 判据 ② 必须用**不掩码**的 attention：因果掩码本身依赖位置（第 i 行只看前 i+1 个），重排后掩码语义已变，差必然大，但那是掩码造成的。
- 配对布局（相邻 `2k,2k+1` vs 前后半 `i, i+d/2`）是**约定**而非数学要求：两套实测都保范数（变化 0.0），结果差 **3.295**，且不是列重排 ⇒ 换布局 = 换模型，权重绑定布局。

### 频率表（`div`）为什么这么取

`div_k = 10000^(−2k/d) = 10^(−8k/d)`，四个性质：

| 项 | 值 / 规律 |
|---|---|
| 个数 | `d/2`（一个频率供两维：sin 一列、cos 一列） |
| 相邻比 | `10^(−8/d)`：d=4 → 0.01 · d=8 → 0.1 · d=16 → 0.3162 · d=512 → 0.9647 |
| 端点 | `ω_0 = 1`；`ω_{d/2−1} ≈ 1e-4`（与 d 无关） |
| 波长 | `2π/ω` ∈ [6.3, 62 832] 个位置 |

- **为什么要多频**：单频在 `2π` 整数倍上完全重复 —— 实测位置 0 与 44（`44 ≈ 7×2π`）的向量差只有 **0.0177**；多频（8 维）100 个位置的最小距离升到 **0.6453**（36 倍）。
- **为什么除 d**：保证频段与维度数无关，d 只改密度。不除则 d=512 时指数到 −510，`10000^−510` 下溢成 0，后半维度全废。
- **为什么是 `-` 指数**：i 越大频率越小、波长越长 ⇒ 低维快、高维慢（多尺度时钟）。

### RoPE 的两行公式 = 复数乘法

```
(xe + i·xo)(cosθ + i·sinθ) = (xe·cos − xo·sin) + i(xe·sin + xo·cos)
```

- 那个负号来自 `i² = −1`，不是人为规定；两个都取 `+` ⇒ 行列式 `cos²−sin² ≠ 1`，实测把 `(1,1)` 的范数从 1.4142 拉到 1.9191。
- θ=90° 时退化成 `(x,y) → (−y,x)`，是"确实是旋转"的直白证据。
- 点积只剩相位差：`⟨R_m q, R_n k⟩ = Re(q·conj(k)·e^{i(m−n)ω})`，实测与两行公式差 **1.11e-16**。

### torch 侧今天核到的四条

| 现象 | 原文 / 数字 |
|---|---|
| 高维 `.T` 已废弃 | `The use of x.T on tensors of dimension other than 2 to reverse their shape is deprecated`（torch 2.11）⇒ 用 `x.mT` / `x.transpose(-2,-1)` |
| 1 维 `.T` 是空操作 | `pos.shape (4,)` → `pos.T.shape (4,)`，`torch.equal` 为 True ⇒ 变竖排要 `unsqueeze(1)` |
| `int / int` 落 float32 | `10000 ** (-arange(0,4,2)/4)` 得 `0.009999999776482582`，与 float64 的 0.01 相对差 **2.2e-08** ⇒ `dtype=torch.float64` 要显式 |
| `std()` 默认无偏 | 官方 `correction=1`；N=64 时比 `correction=0` 高 **0.79%**，N=4096 时只差 **0.012%** |
