# 2026-11-03（周二）· S0·httpx 提前落地：一次 HTTPS 请求的两张账单

## 三句话复盘

1. **最大收获**：两个实验把「网络耗时」拆成了**账单上不同的两行** —— 判据 4 省的是**握手费**（新建 3.431 s vs 复用 1.573 s，每请求 ≈ 0.37 s 的 TCP+TLS 费，`Client` 连接池把它留住）；判据 6 省的是**等待重叠**（串行 7.036 s vs `gather` 1.723 s，**4.1×**）。同一条定律「**等待不占 CPU，所以能叠**」在两种成本结构上各复现一次 —— 和上周 `serial 2.02 s` vs `gather 1.00 s` 是同根。
2. **最大教训**：随堂测两轮暴露「**判决力够、机制力欠**」—— 6 题结论全对，但"为什么"普遍只到第一层（漏 `await` 的错误**后移**到用结果的地方、单批共享 client 与各开 client 账单几乎相同而**差别在第二批**、并发换不同主机是**短板效应**，全是补课后才补齐）。机制层 = 周日盲写的靶子，已在回访清单立了三条靶。
3. **明天第一步**：**OOP 与协议**（class / dataclass / Protocol / `__dunder__`），判据 = 用 dataclass 写一个**带校验**的数据模型；同时要校准一件事 —— 今天把原排期 11-05 的 httpx 提前做掉了，**函数与模块**（`*args/**kwargs`、装饰器、闭包、`import`）被挤掉还没做，明天定它插哪格（候选 = 11-05 的剩余格；S0 交付物死线 11-06 不动）。

## 今日沉淀

| 领域 | 内容 | 关键判据（可复测） |
|---|---|---|
| **请求/响应模型** | GET = 按门牌号寄信，**不是去某处"查找"**；URL 拆两半：主机走连接层（DNS→TCP/TLS），路径进请求行；服务器是**路由匹配的程序**不是文件柜（`/delay/1` 后面没有存好的文件） | `httpbin.org/get` 回的是**请求回声** JSON（含自己的 headers） |
| **`params` 与 URL 对象** | `params` 把拼接+percent-encoding 交给 httpx（手工拼 `好` → 漏成 `%E5%A5%BD`）；值全是文本（写 `"1"`）；`r.url` 是 URL 对象，`in` 直接 `TypeError` → `str(r.url)`；更严的验法 = `r.url.params["q"]` | `q=httpx` 与 `page=1` 同时出现在查询串；dict 顺序不重排但判据用 `in` 不依赖顺序 |
| **`raise_for_status()`** | httpx 默认**不把状态码当异常**（404 是服务器好好回的话）；`raise_for_status()` = 显式决定"当错误"：非 2xx 抛、2xx **返回 Response 可链式**；3xx **不算**错误（默认不跟随重定向） | `/status/404` → `HTTPStatusError: 404`；`httpx.get(url).raise_for_status().json()` 合法 |
| **异常两支是兄弟** | `RequestError`（请求没走完，带 `.request`）∥ `HTTPStatusError`（走完但非 2xx，带 `.response`），基类 `HTTPError`；**互不为子类 ⇒ `except` 顺序无所谓**；坏域名在 `get()` 内部就抛（连接没建立 ⇒ 没有响应可言） | `no-such-host.invalid` → `RequestError`；两条 try 分开写 = 两个探针互不拖累 |
| **Client 连接池** | 一次 HTTPS 首请求 = DNS + TCP 三次握手（1 RTT）+ TLS（1-2 RTT，证书防冒充 + 对称密钥提速）+ HTTP 往返；顶层 API **每请求各付全套**，`Client` 复用 keep-alive **只付一次** | 5 × `/get`：新建 **3.431 s** vs 复用 **1.573 s**（**2.2×**，差 ≈ 0.37 s/请求） |
| **"复用快"的精确边界** | 并发批共享 client **照样开多条新连接**（握手互相重叠）⇒ **单批两种写法账单几乎相同**；省的钱在**第二批**（池里 keep-alive 还活着，零握手）—— "别在热循环实例化 client"的损失在**复用**不在单批 | 判据 4 两组请求数**完全相同**（都是 5 个），读反 = 实验设计反 |
| **`gather` 的机制** | `tasks = [fetch_one(...) ...]` 此刻**零请求**（只是协程对象 = 工单）；`gather(*tasks)` 拆包提交、结果**按传入顺序**返回；`*` = 调用时**拆包**（定义时 `*args` 是**打包**），不拆 = 整个列表当一个参数 → **`TypeError`** | 5 × `/delay/1`：串行 **7.036 s** vs 并发 **1.723 s**（**4.1×**） |
| **短板效应（回访 #43）** | `gather` 要等**全部** ⇒ 抓不同主机时总耗时 ≈ **最慢单个**；并发批的超时按最慢者算，配 `return_exceptions` 防一个拖垮全场 | 同主机同延迟才近似"并发 ≈ 单个" |
| **漏 `await` 的错误后移** | `fetch_one(client, u)`（漏 await）→ 当下不报错、耗时 ≈ 0；列表里装协程对象；退出时 `RuntimeWarning: never awaited`；判据 7 断言 `TypeError` —— **错在案发现场之外** | 静默 bug 经典形态（回访 #19 的实战版） |
| **计时纪律（回访 #42）** | 单样本 = 随机变量 + 先跑的批付冷启动费 ⇒ **只记数字、复跑取稳态、不写死 assert**；读数要拆账，别只看加速比 | 串行批先跑：DNS 几十 ms 在 7 s 里是零头，不翻案 |
| **工具链三条** | ① `open` 的 `mode="r"` 是默认值 → Pylance 灰 hint「Unnecessary mode argument」（红 error / 黄 warning / 灰 hint 分级）② `uvx ruff format` 又补函数间空行（`E302` 不在 `check` 默认规则集，**第 4 次踩**）③ docstring 长行 `E501`：拆两行，别 `noqa` | ruff `check` + `format --check` 最终全绿 |
