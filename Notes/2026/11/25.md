## 三句话

1. **最大收获**：真训练 = 把四块零件接上电源（数据 → 基线 → 模型 → 梯度下降），**唯一的判据是数字往对的方向走**：2000 步后 val CE 从 **4.3175 → 1.7983** nats/char（6.23 → **2.594 bits**），**低于 bigram 基线 2.4819 达 27.5%**；显存峰值只有 **0.322 GiB**（上限 6），**45.7 s** 跑完 2000 步（22.9 ms/步，8192 token/步 ⇒ 约 358k token/s）。

## 今日沉淀

### 数据侧：一句「右移一位」扛起整条链路

| 环节 | 事实 | 数字 |
|---|---|---|
| 语料 | tiny shakespeare，纯 ASCII | **1,115,394** 字符 / **65** 个不同字符 |
| 词表 | `sorted(set(text))`，编号只由排序决定 | `itos[0] == '\n'`、`stoi['e'] == 43` |
| 切分 | **按位置**切 9:1，不 shuffle（shuffle 会让 val 的上下文在 train 出现过） | train **1,003,854** / val **111,540** |
| 采样 | 随机 offset 抠 128 字符窗口，`y = x` 右移一位 | 2000 步 × 64 × 128 = **16.38 M token** ≈ 训 **16 遍** |

**offset 上界要分清两个数**：合法 offset 最大 = `len - block - 1`；而 `torch.randint(high)` 取不到 high，所以 `high` 至少要是 `len - block`。写成 `len - block - 1` 是**保守一位**（少用一个窗口，无害）；**真正会炸的是 high 偏大**——`y` 的右端越界后 PyTorch 切片**静默变短**，最后由 `stack expects each tensor to be equal size` 报出来（实测 len=10/block=3：o=6 合法，o=7 起短一位）。

### 基线侧：bigram 的四个口径

| 口径 | 内容 | 数字 |
|---|---|---|
| 计数 | `bincount(ids)` + `bincount(ids[:-1]*V + ids[1:])` 压平再 reshape | `sum(C_bi)` **1,003,853** = len−1、`sum(C_uni)` **1,003,854** = len |
| 分母 | 用 **`C_prev`（行和）**，不是 `C_uni` | 差 1（末字符没有后继）；用 `C_uni` 会让行和偏 **1.17e-05** |
| 平滑 | add-k，分母加 **`k·V`**（这行有 V 个格子） | 漏 `k·V` 行和偏 **6.5**；k 三档 **2.4819 / 2.4838 / 2.4875** |
| 单位 | **nats/char**（bits = nats ÷ ln2） | 基线 **2.4819** nats = **3.5806** bits；unigram 3.3473 |

两个可迁移的结论：

1. **k 不是「越小越好」**：本语料未见对只占 **0.168%**（187/111,539），最优点反而在 **k≈1**（扩档验证 k=2/5/10/30 = 2.4829/2.4877/2.4968/2.5323）。k 的最优值取决于语料规模与未见比例。
2. **分母选错 = 换了目标**：用全表总和 ⇒ 算的是联合熵 \(H(X,Y)\)，比条件熵 \(H(Y|X)\) 高出的部分**恰好是 `H(前一个字符) = 3.3091`**（实测 5.7613 − 2.4522 = 3.3091）。

### 模型侧：block 的两类「混合」不能混

| 子层 | 混哪一维 | 实测（改位置 3 的第 0 通道 +1.0） |
|---|---|---|
| 注意力（SDPA `is_causal`） | **位置**（token ↔ token） | 位置 3 及之后全变，0–2 不变 |
| FFN（`GELU` 夹两个 Linear） | **通道**（feature ↔ feature） | 只有位置 3 变，但 **128/128** 个通道都变 |

- 参数分布（每层 198,272）：qkv **49,536** + proj **16,512** + FFN **131,712**（**66%**）+ LN 512 ⇒ 全模型 **826,368**。
- `head` 的 `bias=False` 省 65 个参数；`nn.Linear` 的 weight 是 `(out, in)`，所以 3a 里写 `self.wq(z)` 不需要 `.T`（关 3 手写版存的是 `(in, out)` 才要）。
- 因果性两路取证：改末位后 **过去严格 0**、**末位 1.750**（残差直通，恰好等于扰动量级）。

### 训练侧：一个循环里的六个「必须」

| 顺序 | 动作 | 漏了会怎样 |
|---|---|---|
| 1 | `opt.zero_grad(set_to_none=True)` | 梯度**累加**，等效学习率越跑越大 |
| 2 | `get_batch(...)` + `.to(dev)` | 数据在 CPU、参数在 GPU ⇒ `Expected all tensors to be on the same device` |
| 3 | `model(x, y)` 前向 | — |
| 4 | `loss.backward()` | 没有 `.grad`，`step()` 空转 |
| 5 | `clip_grad_norm_(..., 1.0)` | 一次性大梯度打穿参数（fp32 下少见，成本极低） |
| 6 | `opt.step()` | 白算一场 |

三条配套纪律：**训练/评估两个 generator 分开**（否则评估采样插进训练流、不可复现）；**评估必须 `no_grad`**（否则 20 个 batch 的图挂在显存里）；**显存先 `reset_peak_memory_stats`**（否则把之前所有前向都算进峰值）。

### 生成侧：「最长重复片段」必须先定义

判据里这句话至少有三种解释，不同解释给出不同数字。本关写死为：**最长重复子串（至少出现两次、允许重叠）**，`dp[i][j] = 1 + dp[i+1][j+1]`，`O(n²)`，`"aaaa"` 的最长重复是 `"aaa"`（长度 3）。

解码参数提前定死：**temperature 0.8 + top_k 40**（贪心在小模型上极易死循环、纯采样噪声太大）。实测样本有 `COMINIUS:` / `HENRY BOTHAK:` 这样的人名行与空行 ⇒ **学到了排版结构**，但词汇是坏的（`dost grantly good`）——这正是 1.8 nats 该有的样子。
