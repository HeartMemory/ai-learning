### 四段公式

```
cost = (cached × p_缓存 + (prompt − cached) × p_入 + completion × p_出) / 1e6
```

- `prompt_tokens` **已包含**命中部分 ⇒ 未命中段必须 `prompt − cached`，写成 `prompt × p_入 + cached × p_缓存` 会把命中部分算两遍；
- `reasoning_tokens` **不参与计价**（思考按输出价算，官方无单独价格项）。

### 上游给什么、不给什么

- 原生 API **只回 token 数**（`usage` 里没有任何金额字段）；OpenRouter 那类网关回传的 `cost` 是网关扩展（还带加价），不能当官方价；
- 钱是我们按单价乘出来的**折算值**，账单在平台侧另算（推理账单分钟级出账，实测 token 数字 **40 分钟**才可见）；
- 平台按**请求名**分组：别名 `deepseek-v4.1-flash` 与快照名 `deepseek-v4.1-flash-1017` 是**两栏**，对账要按实际请求的那个名字筛。

### 三版 prompt 实测（同一任务 10 条输入）

| 版本 | 前缀 | 输入 | 命中 | 输出 | 成本 | 每分成本 |
|---|---|---|---|---|---|---|
| short | 88 字符 | 706 | **0** | 689 | 0.0069 | 0.000239 |

- 效果**打平**（修正判据后三版都是 29/30）⇒ 这个任务上长 prompt **没换来可测量提升，只加 43% 成本**；

- 边界题（"明年价格会不会涨"）三版都答错，只有 long 首轮碰对 —— **单次测量不可判定**（思考模式 `temperature` 不生效）。

### 超长输入：截断不该出现

- 超限 = `400 Range of input length should be [1, 1048576]`，**服务端不裁剪历史**（官方 FAQ：「遇到上下文超限相关的报错时建议新建会话」+ 关卡 3 实测互证）；
- **分段总结省不了输入 token**：5 万 token 文档，全量一次 `0.1064` 元 vs 分 5 段 `0.1164` 元（输入总量不变，还多一层输出）；
- 分段还**不可逆地毁掉全局信息**（每段不知道全文）⇒ 截断/分段不该作为默认策略；
- **正解是压缩上下文**（摘要替原文），只对"同一段内容反复重发"有意义 = 多轮历史，留给 L5 / coach。

## 踩坑

1. **`completion_tokens` 含思考 token —— 第三次栽在同一个坑**：判据写成 `completion ≤ 30`，等于要求模型不许思考，30 条只过 1 条，把首轮结论带偏。
2. **`str.strip("` \n")` 是字符集剥离**：`strip('json')` 会把正文两端的 j/s/o/n 随机砍掉，实测 `{"category": "tech"}n`（不合法）被判成合法 —— 围栏要么"判断 + 切片"，要么干脆判不合规。
3. **`¥` 在 GBK 控制台下崩**：管道接住 stdout 时编码是 cp936，`¥`（U+00A5）与全角竖线都会 `UnicodeEncodeError`，且崩在**钱已经花掉之后**。
4. **`ZoneInfo("Asia/Shanghai")` 在 Windows 直接炸**（缺 IANA 时区库，要装 `tzdata`）⇒ 本机用 `timezone(timedelta(hours=8))` 固定偏移更省事。
5. **判据"外部取证"必须考虑平台精度**：0.002 元在任何按元 2 位小数的界面都是 `0.00`，只能退到"token 合计"或"调用次数"这一级。

# 下午追加：L2 关卡 1（单头算术）· 2026-11-22

> 上午那条「明天第一步」已被本节取代：主线顺序定为 **L2 → L3 → L5**（先补原理段，再进 agent）。

## 三句话

1. **最大收获**：attention 的全部内容就是「算一组比例，再拿它把 V 掺起来」—— `Q·Kᵀ/√d` 决定该听谁（W 是 T×T），`softmax` 把分数变成合法比例（行和 = 1 是**约束**，列和不是），`w@V` 按比例加权平均（凸组合，结果不等于任何一行 V）。
2. **最大教训**：**阈值必须等噪声测完再定**。判据 ② ① 先按「单次比值误差 < 5%」写，实测同一份代码比值在 14.8~18.4 之间乱摆 ⇒ 会随机红；根因是同一行的格子共享同一个 `q` 行向量、不是独立样本。改成 10 seed 平均后才稳。
3. **明天第一步**：**L2 关卡 2「掩码与位置」**（改未来不影响过去 / 置换等变 / 加位置编码后差 > 1e-3）。

## 今日沉淀

### 四个矩阵各自的形状（最容易混的一处）

| 矩阵 | 形状 | 每行代表 | 进输出吗 |
|---|---|---|---|
| Q | T×d（4×2） | 第 i 个 token 的「我要什么」 | 不进，只参与算权重 |
| K | T×d（4×2） | 第 i 个 token 的「我有什么」 | 不进，只参与算权重 |
| V | T×d（4×2） | 第 i 个 token 的「内容」 | **进**（输出是它的凸组合） |
| **W** | **T×T（4×4）** | 第 i 个 token 对全场的**分配比例** | 不进 |

- 「关注度」只在 **W** 里；Q/K 每一行只是该 token 自己的两份表述，**单看一行没有关注度信息**。
- W 之所以是 T×T：关注度是**两两之间**的量；Q/K/V 是 T×d：只描述自己。

### Q/K 为什么不能共用一份

用同一份向量时分数矩阵 `x·xᵀ` **必然对称**（实测 `torch.equal(s, sᵀ) = True`，`s[0][3] == s[3][0]`）⇒ 表达不了「token i 单方面需要 token j」。拆成 Q/K 后不对称（实测 `s[0][3]=0` 而 `s[3][0]=2`）。

### 三个反复问到的点（结论）

- **权重不是「配对概率」**：列和实测 `[1.0113, 1.0464, 1.2932, 0.6492]`（不归一）、`w[0][3]=0.1651 ≠ w[3][0]=0.4022`（不对称）、全程无随机 ⇒ 它是「第 i 个 token 的预算怎么分」。
- **不是「只拿一部分字符」**：被按比例缩放的是**向量**，取 0.4 倍就是取 40% 的特征强度；attention 输出不是字，是中间表示，只有最后输出层才变回字。
- **输出不是「下一个 token」**：T 个进、T 个出、位置一一对应，同位置 token 的**表示**被上下文改写（「苹果」在两种语境得到两个向量）。

### 为什么必须除 √d（判据 ② 的因果链）

`d` 越大点积量级 ≈ √d ⇒ softmax 越尖 ⇒ 饱和成 one-hot ⇒ 梯度趋 0（L3「训练不动」的前因）。实测 d=512 未缩放时 maxw **1.0000**、熵 **0.2454 bit**；除 √d 后回到 **0.2747 / 5.3109 bit**。

## 踩坑

1. **`✓`/`✗` 在 GBK 控制台崩**：`UnicodeEncodeError: 'gbk' codec can't encode character '\u2713'` ⇒ 判据输出只用 ASCII（`OK` / `NG`）。与上午 `¥` 那条同类，都是**中文 Windows 控制台编码**。
2. **单 seed 的比值噪声 ±15%**：`std` 比值在 14.8~18.4 之间摆，`(64,64)` 同行共享同一 `q` 行 ⇒ 有效样本远小于 4096 ⇒ 统计判据必须多 seed 平均。
3. **`numel()` 不是行数**：熵要按行平均（`w.shape[0]`），误除 4096 会把 6 bit 变成 0.094。
4. **手算半边由 AI 代写 ⇒ 判据 ① 独立性降级**：两条路同源，绿了只证明「AI 的实现和 torch 一致」。补了「改动预测三题」复核 3/3，记为**降级通过 · 已复核**。
5. **`ruff` 两处小坑**：给无占位符的字符串加了 `f` 前缀（F541）；编辑器自动补 `import math` 造成 F811 重复导入。
