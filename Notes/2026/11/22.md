| 计费项 | 闲时（22:00–次日 08:00） | 忙时 |

同一模型的 DeepSeek 官方页（USD）非高峰 `$0.15 / $0.60` per 1M ⇒ 按 ~7.1 折 ≈ ¥1.07 / ¥4.26，与百炼闲时价同一量级，互证成立。

### 四段公式

```
cost = (cached × p_缓存 + (prompt − cached) × p_入 + completion × p_出) / 1e6
```

- `prompt_tokens` **已包含**命中部分 ⇒ 未命中段必须 `prompt − cached`，写成 `prompt × p_入 + cached × p_缓存` 会把命中部分算两遍；
- `reasoning_tokens` **不参与计价**（思考按输出价算，官方无单独价格项）。

### 上游给什么、不给什么

- 原生 API **只回 token 数**（`usage` 里没有任何金额字段）；OpenRouter 那类网关回传的 `cost` 是网关扩展（还带加价），不能当官方价；
- 钱是我们按单价乘出来的**折算值**，账单在平台侧另算（推理账单分钟级出账，实测 token 数字 **40 分钟**才可见）；
- 平台按**请求名**分组：别名 `deepseek-v4.1-flash` 与快照名 `deepseek-v4.1-flash-1017` 是**两栏**，对账要按实际请求的那个名字筛。

### 三版 prompt 实测（同一任务 10 条输入）

| 版本 | 前缀 | 输入 | 命中 | 输出 | 成本 | 每分成本 |
|---|---|---|---|---|---|---|
| short | 88 字符 | 706 | **0** | 689 | 0.0069 | 0.000239 |
| mid | 207 字符 | 1326 | **0** | 531 | 0.0069 | **0.000238** |
| long | 568 字符 | 3186 | **1024（32%）** | 691 | 0.0099 | 0.000341 |

- 效果**打平**（修正判据后三版都是 29/30）⇒ 这个任务上长 prompt **没换来可测量提升，只加 43% 成本**；
- 缓存把 long 的输入成本打掉一大截：两轮命中率 **64% / 32%**，波动来自官方"尽力而为"；short / mid 因前缀不到 256 token **恒 0**；
- 边界题（"明年价格会不会涨"）三版都答错，只有 long 首轮碰对 —— **单次测量不可判定**（思考模式 `temperature` 不生效）。

### 超长输入：截断不该出现

- 超限 = `400 Range of input length should be [1, 1048576]`，**服务端不裁剪历史**（官方 FAQ：「遇到上下文超限相关的报错时建议新建会话」+ 关卡 3 实测互证）；
- **分段总结省不了输入 token**：5 万 token 文档，全量一次 `0.1064` 元 vs 分 5 段 `0.1164` 元（输入总量不变，还多一层输出）；
- 分段还**不可逆地毁掉全局信息**（每段不知道全文）⇒ 截断/分段不该作为默认策略；
- **正解是压缩上下文**（摘要替原文），只对"同一段内容反复重发"有意义 = 多轮历史，留给 L5 / coach。

## 踩坑

1. **`completion_tokens` 含思考 token —— 第三次栽在同一个坑**：判据写成 `completion ≤ 30`，等于要求模型不许思考，30 条只过 1 条，把首轮结论带偏。
2. **`str.strip("` \n")` 是字符集剥离**：`strip('json')` 会把正文两端的 j/s/o/n 随机砍掉，实测 `{"category": "tech"}n`（不合法）被判成合法 —— 围栏要么"判断 + 切片"，要么干脆判不合规。
3. **`¥` 在 GBK 控制台下崩**：管道接住 stdout 时编码是 cp936，`¥`（U+00A5）与全角竖线都会 `UnicodeEncodeError`，且崩在**钱已经花掉之后**。
4. **`ZoneInfo("Asia/Shanghai")` 在 Windows 直接炸**（缺 IANA 时区库，要装 `tzdata`）⇒ 本机用 `timezone(timedelta(hours=8))` 固定偏移更省事。
5. **判据"外部取证"必须考虑平台精度**：0.002 元在任何按元 2 位小数的界面都是 `0.00`，只能退到"token 合计"或"调用次数"这一级。
