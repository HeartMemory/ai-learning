# 2026-11-20（周五）· L4 关卡 1：流式 —— 首 token 与「不可判定的逐字符相等」

## 三句话复盘

1. **最大收获**：流式的收益**只在首字延迟**上。5 次实测首 token 中位 **567.15 ms**、总时长中位 **2219.08 ms**（占 25.6%）；同一 prompt 的非流式中位 **2287.47 ms** —— 比流式只慢 3%，说明「流式让回答更快」这句话是错的，它只是**让你更早看到第一个字**。
2. **最大教训**：判据 ②（流式拼出的文本 == 非流式文本，逐字符相等）第一次跑是 `False ｜ 分歧下标 0 ｜ 长度差 +3`。但**这不是拼接 bug** —— 拼接只能造成丢字 / 重复 / 乱序，造不出「两段开头措辞完全不同」。查证后确认：测试模型默认开**思考模式**，而思考模式下 `temperature` / `presence_penalty` / `frequency_penalty` **收下不报错、也不生效** ⇒ 两次请求都是不可控采样，判据 ② 变成「**不可判定**」。关思考 + `temperature=0` 后分歧下标从 **0 推到 43**（温度确实生效），但供应商仍非确定（输出 token 183 vs 207）；最终换**低熵任务**（「从 1 数到 30」）才拿到 `True ｜ -1 ｜ 0`。
3. **明天第一步**：L4 关卡 2（结构化输出）第一块 —— 先把「20 次里 ≥19 次 schema 通过」的判据拆成可执行的校验层，再动手写。

## 今日沉淀

| 领域 | 内容 | 关键判据（可复测） |
|---|---|---|
| **流式的收益边界** | 省的是首字延迟与可中断性；**总时长、token、费用一样** | 流式 2219 ms vs 非流式 2287 ms（差 3%）｜首 token 占 25.6% |
| **首 token 的口径必须写死** | = **正文首个非空 `delta.content`** 的到达时刻，不含 role 帧 / 终止帧 / 账单帧 / 纯思考帧 | 口径不同数字差很大，跨模型不可比；本关写进项目 README「设计取舍」 |
| **`for` 循环为什么「不会提前结束」** | `for` = 反复调 `__next__`，每步阻塞在 `iter_bytes()` 读 socket；结束条件只有 `[DONE]`、对端关连接、异常、自己 `break` | 对端**关连接但不发 `[DONE]`** ⇒ 循环**平静退出、无异常** ⇒ 「循环结束 ≠ 成功」 |
| **账单是「总计」不是「增量」** | 正文发 `delta`（差量，要自己拼），账单发 `usage`（整次总量，只出现一次） | `stream_options={"include_usage": True}` ⇒ 末尾多一条 **`choices` 为空**的帧，取 `choices[0]` 前必须判空 |
| **中断拿不到账单** | 官方原文：*"If the stream is interrupted, you may not receive the final usage chunk"* | ⇒ `StreamAnswer` 三个 token 数是 `int \| None`；半截的账不存在，不许填 0 |
| **流消费不自动重试** | 普通请求默认重试 2 次；**流一开就不再重试**（重放会重复输出） | 读超时 → `APITimeoutError`；其它连接失败 → `APIConnectionError`，原始异常在 `__cause__` |
| **`break` 自动关连接** | SDK `_streaming.py` 的 `__stream__` 有 `finally: response.close()` | 循环里 `break` 不需要自己 try/finally |
| **思考模式与采样参数** | 思考模式**不支持** `temperature` / `presence_penalty` / `frequency_penalty`（收下不生效）；`top_p` 在该模型**非思考模式恒 1.0**、思考模式 0.95–1.0 | 关思考 + `temperature=0` 后，两次生成的前 **43 字符**逐字节一致（开思考时下标 0 就不同） |
| **思考模式的隐形成本** | 同一 prompt：思考模式输入 **45** token，关思考 **19** token | ⇒ 思考模式自带约 **26** 个输入 token 的隐藏模板，`messages` 里看不见但每次都付费 |
| **`reasoning_content` 的位置** | 流式时在 `delta.reasoning_content`，**与 `content` 同级、不同时非空**；非流式在 `message.reasoning_content` | 带 `tools` 的会话**必须回传**历史 `reasoning_content`，漏了直接 **400** |
| **`print` 的缓冲三层** | 字符串本身不含换行 → `print` 默认补 `\n` → stdout 缓冲：终端**行缓冲**（遇 `\n` 吐）、管道 / 文件**块缓冲**（本机 **128 KiB**） | `end=""` 去掉了 `\n` 就失去行缓冲触发器 ⇒ 边打边输必须 `flush=True` |
| **测量口径：中位数 vs 平均值** | 首 token 中位 567.15、均值 **648.54**（差 14.3%，第 3 次 1059 ms 是异常值）；非流式中位 2287.47、均值 **2359.78**（第 1 次 2989 ms 是冷启动） | 判据写「中位数」不是洁癖：平均值在 5 次里就被拖歪 14% |

| 指标 | 数值 |
|---|---|
| 模型调用 | **14 次**（10 次 bench + 4 次诊断）｜输入 token 约 **0.4 K**、输出 token 约 **2.6 K** |

| 文档改动 | 项目 README **+2 节 +8 行表格** ｜ AI 册 **+1 章** ｜ 回访清单 **+3 条** ｜ 根 README **+1 打卡行** |

⭐ **一个可复用判据**：**「判据红了，先问它到底测的是哪两件事。」**
「流式文本 == 非流式文本」其实同时测了 **拼接无损** 和 **两次生成相同** 两件事。供应商非确定时，第二件事不可控，判据就变成不可判定 —— 这时不该改判据凑绿，而该**找一个能把两件事分开的实验**（低熵任务）。同一句话也适用于测环境：`temperature=0` 不是「确定」的同义词，先验证它到底有没有生效。
