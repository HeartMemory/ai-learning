# 2026-11-19（周四）· L1 关卡 4：平滑 —— L1 四关收口

## 三句话复盘

1. **最大收获**：`inf` 其实是**两种病**。84 个位置里，26 个是「行存在、缺列」（`c=0`，add-k 能治），41 个是**位置里有生字**（不在候选集里，连「垫过的 0」都不存在）⇒ 只加平滑不动词表，held 的 CE **仍然是 `inf`**（实测 V=158 时 24 个位置概率为 0）。所以本关真正的解法是两件事叠加：**闭词表 V = 158 + `<UNK>` = 159** + add-k。实测 `inf` → **7.0590 / 6.7812 / 8.4070**（k = 1 / 0.1 / 0.001 bit/char）。
2. **最大教训**：**变异 M6（跳过位置但分母不变）第一轮 8 条判据全绿**。它只让 held 的数字悄悄变低（**1.2038 vs 真值 7.0590**）—— 归一化判据管的是概率表，管不到「平均口径」。补**两路互证**（逐位置 vs 按对加权，差 < 1e-12）才红（漏网时差 **5.855**）。⇒ 判据要分两班岗：**概率表归一一班、平均口径一班**。
3. **明天第一步**：L2（注意力）还没拆判据 —— 先按阶段表把 L2 拆成可判的关卡（单头 attention → 最小 Transformer block），别直接动手写 attention。

## 今日沉淀

| 领域 | 内容 | 关键判据（可复测） |
|---|---|---|
| **add-k 的两种写法** | `(c+k)/(C+k\|V\|)` = `C/(C+k\|V\|)·P_MLE + k\|V\|/(C+k\|V\|)·1/\|V\|` —— 右边是**凸组合**（权重和为 1 ⇒ 归一白送） | 三行 × 三个 k：键集 == 闭词表、和 = 1（±1e-12）、全正 |
| **分母为什么加 `k\|V\|`** | 分子给 V 里**每个**候选都加了 k，总加量 `k\|V\|`；分母不加回去行和就 ≠ 1 | 漏写实测行和 **7.8696**（M1） |
| **只给「见过的列」垫 k 是错的** | 行和能凑到 1，但分母变成 `C + k·已见列数` ⇒ 数字随「碰巧见过几列」飘，跨模型不可比 | 行和 **0.9006** 就露馅（M3） |
| **`C=0` 的整行** | `P = k/(0+k\|V\|) = 1/\|V\|`，整行均匀；`<UNK>` 当上下文天然是这种 | `<UNK>` 行 159 项全等 **0.006289** |
| **移走的质量** | `k\|V\|/(C+k\|V\|)`：随 \|V\| 变大、随 C 变小 | k=1 最惨行 `'清'`（C=1）= **159/160 = 0.99375** |
| **`<UNK>` 与闭词表** | 训练时定死 V，评估时把生字折叠；`<UNK>` 训练计数 0 ⇒ 概率全来自垫的 k | 折叠：token **85→85**、全 ∈ 闭词表、幂等、老字不动 |
| **`<UNK>` 是 5 字符 1 token** | `"".join(tokens)` ⇒ 85 token 变 **181** 字符，位置 84→**180**，CE 全错**且不报错** | 断言 `len("".join(tokens)) != len(held)` |
| **k 不是越小越好** | k→0 退回 MLE：**train 变好、held 变差**（UNK 位置概率被压到 1e-5，每位置 ~15 bit） | held：1.0 → 7.0590 · **0.1 → 6.7812（最优）** · 0.001 → 8.4070 |
| **平滑的代价必须可见** | 训练集 CE 单调升高，且 k 越大越痛 | train：1.2943 → 6.1048 / 3.8545 / 1.3944 |
| **可比性五同** | 同一 held、同一位置集合（84）、同一 V（159）、同一底数（log2）、同一折叠规则 | 判据钉 `len(vocab) == len(set(train)) + 1 == 159` |
| **CE 单位** | `bit → nat` 是 **×ln2（÷1.4427）**；`ppl = b^{CE_b}` 与底数**配对抵消** | 1.2943 bit 与 0.8971 nat 的 ppl 都是 **2.45** |

## 加练 2：L4 关卡 0（打通与记账 · 交付物 `projects/llm-cli/`）

L2 关卡 0 之后从 L2 插队到 L4：先把「一次调用 + 记账」做成**能演示的命令行**（后面流式 / 结构化 / 成本三关都长在它上面）。

**骨架与分工**：`llm_cli/` 一个包 —— `config.py`（AI 写，`.env` → `Settings`，绝路径 + `api_key` `repr=False`）、`cli.py` 的 `build_parser()`（AI 写机械部分）、`llm.py` 的 `ask()` 与 `cli.py` 的 `main()`（**本人写**，镜子 = `10/29-llm-hello/ask.py`）。

**三条真踩到的坑（都写进了交付物 README）**

1. **类型收窄只作用于被判断的表达式**：`if usage is None: raise` 之后再写 `response.usage.prompt_tokens`，Pylance 照报 `reportOptionalMemberAccess` —— 因为属性访问是**重新读一次**，不是同一个名字。判空后必须用变量 `usage`。
2. **`finish_reason` 在 `choices[i]` 上，不在 `message` 上**：`message` 只有 `content` / `refusal` / `role` / `tool_calls`。写 `message.finish_reason` 直接「属性未知」。
3. **「没正文」不等于「没花钱」**：`finish_reason` 取值里有 `length`（截断）/ `content_filter`（被拦）/ `tool_calls` —— 三种情况 token 照扣。所以正文为空**不能抛错**（那会把账单一起扔掉），正确处理 = 打印账单 + `return 3`，让退出码表达失败。⇒ 由此定下**记账与成败判定分离**：`usage` 拿不到才抛（真无法记账），正文拿不到只算「这条命令失败」。

**决策记录（判据要的是「做过选择」）**：正文 `None` → `content or ""` 兜底；`usage` 缺失 → `RuntimeError`；请求异常（401/429/超时）**当前不接**、让其冒泡（退出码仍是 1）。
