# 2026-11-26（周四）· L3 关卡 0 基线可复现

## 三句话

1. **最大收获**：**seed 只固定「抽到哪些随机数」，不固定「浮点按什么顺序相加」**。同一份代码、同一个 seed 连跑两次：前 40 步逐步 CE 差 < 1e-9，第 **40** 步起出现 **1e-06** 的差，一路放大到 **1.944e-02**（step 1236），终值 val CE 差 **6.397e-03**（1.806031 vs 1.799635）—— 1400 步里 **1371 步**有差。
2. **最大教训**：**要复现就得付确定性的价钱，而那个价钱得量出来**。开 `CUBLAS_WORKSPACE_CONFIG=:4096:8` + `use_deterministic_algorithms(True)` + `cudnn.benchmark=False` 后，逐步差与终值差都是**严格 0**（0/2000 步有差，1.801704860 == 1.801704860），且跨独立进程仍复现；代价 = 显存 **0.322 → 0.368 GiB（+14.3%）**，耗时 **测不出来**（同一路径 30–50 s 抖动）。
3. **明天第一步**：**L3 五关全绿**（0–4 当天全部收口）⇒ 下一站是 **L5「工具与循环」**：先按「能红、能数出数字」的标准把判据拆成子关，再动手写 mini-agent（禁框架）。

## 今日沉淀

### 复现性分三层，只有第一层归 seed 管

| 层 | 由什么决定 | 本关实测 |
|---|---|---|
| 随机数序列（初始化 / 抽样） | `manual_seed` + 独立的 `Generator` | **完全一致**：前 40 步逐步 CE 差 < 1e-9 |
| 浮点累加顺序 | GPU 上 `atomicAdd` 的线程竞争顺序，**seed 管不到** | 第 40 步起差 **1e-06** |
| 训练动力学（混沌放大） | 上面那一丁点差被 2000 步放大 | 1e-06 → **1.944e-02**，放大 4 个数量级 |

本模型里两个已知的原子累加点：`nn.Embedding` 反向（词表只有 65 个字符，一个 batch 里几千个 token 往同一行梯度上累加）与 SDPA flash 反向的 dQ 累加（PyTorch 2.13 博客明确）。

**为什么判据必须「逐步」比**：终端打印 4 位小数时前 600 步两组曲线一模一样，只有按 1e-9 逐行比才看见 step 40 就已经分叉；而终值 6e-03 这个量级，很容易被误读成「评估蒙特卡洛噪声」。

### 确定性开关三件套

| 开关 | 作用 | 为什么必须 |
|---|---|---|
| `CUBLAS_WORKSPACE_CONFIG=:4096:8` | 给 cuBLAS 一块固定大小的工作区 | CUDA ≥ 10.2 且用 cuBLAS 时**不设它，下一行一开就报错**；且必须写在 `import torch` **之前** |
| `use_deterministic_algorithms(True)` | 让原子累加类算子改走「分桶 / 排序后累加」的确定实现 | 全局总开关；遇到**没有**确定实现的算子直接抛 `RuntimeError`（本机没抛，说明这条路径上的算子都有确定实现） |
| `cudnn.benchmark=False` + `cudnn.deterministic=True` | 关 autotune、只用确定算法 | autotune 会让不同 run 选到不同算法（本模型无卷积，实际不参与，但口径要写全） |

**代价的实测**：显存 **+46 MiB（+14.3%）** 是稳定可测的；耗时在**同批**内无法区分（同一条路径六次：30.4 / 30.5 / 33.4 / 35.3 / 43.7 / 47.0 s —— 首跑要付 kernel 预热与时钟爬升的账）⇒ 「确定性模式慢多少」在这台机器上用耗时是量不出来的，只能报显存。

### 噪声带 = 后面四关的地板

| seed | val CE |
|---|---|
| 1337 | **1.801705** |
| 2024 | **1.782145** |
| 7 | **1.789220** |
| **极差** | **0.019560** |

3 个 seed 的极差 **0.019560 nats/char**（约 1.09 % of 1.80）就是门限：关 1–4 里任何「变好 / 变坏」超过它才算信号，小于它一律记「在 seed 噪声内」。带子里**只含 seed 噪声**，不含「同 seed 重跑噪声」—— 后者在确定性模式下已经被压成 0。

## 关卡 1（lr · 同日完成）

| lr | 终值 val CE | 前 100 步峰值 | 形态 |
|---|---|---|---|
| **1e-8** | **4.3042** | 4.3405 | **不动** |
| 1e-7 | 4.1874 | 4.3384 | 稳降 |
| 1e-6 | 3.3370 | 4.3329 | 稳降 |
| 1e-5 | 2.5432 | 4.3257 | 稳降 |
| 1e-4 | 2.1786 | 4.3257 | 稳降 |
| 3e-4 | 1.8017 | 4.3257 | 稳降 |
| **1e-3** | **1.6113** | 4.3257 | 稳降（最优） |
| 1e-2 | 1.6843 | 4.3257 | 稳降 |
| 3e-2 | 2.9011 | 4.6466 | 稳降 |
| 1e-1 | 3.3488 | **12.6887** | 稳降（早炸后爬回） |
| **1.0** | **91.2485** | **477.2376** | **发散**（首个 CE>10 在第 2 步） |

**结论**：稳值区间 **[1e-7, 1e-1]**；最优 **1e-3**；有效区间（val CE < bigram 基线 2.4819）**[1e-4, 1e-2]**。

三条沉淀：

1. **判据的「三种形态」在本模型上要靠扩档才凑得齐** —— 原文五档 `1e-5…1e-2` 全是稳降（1e-5 都降了 1.77 nats），因为 0.83 M 参数 + AdamW 的稳值区间比预期宽约两个数量级；「不动」要到 **1e-8**，「发散」要到 **1.0**。⇒ 这种「判据档位是按典型模型定的、落到具体模型上凑不齐」的情况，**只能如实记口径偏离，不能改判据凑绿**。
2. **「发散」不等于 NaN** —— lr=1.0 全程没有 inf/NaN，CE 却到 91.25（峰值 477.24）；而 lr=1e-1 前 100 步峰值 12.69 却爬回 3.35。⇒ **峰值（早炸）与终值（真发散）是两件事**，判据要分别卡。
3. **分类器的条件顺序会决定结论** —— 第一版先判「末段在上升」，lr=1.0 因为爆炸后回落被归成「不动」（91.25 ≥ 起点 − 噪声带）。修法：**「终值比不训练还差」必须是发散的第一条**。

## 关卡 2（warmup · 同日完成）

| 组 | warmup | 终值 val CE | 前 200 步峰值 |
|---|---|---|---|
| base（lr=1e-3） | 0 | 1.611282 | 4.3257 |
| base | 100 | **1.607632** | 4.3257 |
| base | 500 | 1.621968 | 4.3270 |
| hot（lr=1e-1） | 0 | 3.348767 | **12.6887**（第 6 步） |
| hot | 100 | 3.359062 | **4.3257** |
| hot | 500 | 3.283613 | **4.3257** |

**结论**：本模型在最优 lr（1e-3）上**不需要 warmup** —— 三档终值极差 **0.014336**，比噪声带 **0.019560** 还小；三档峰值极差只有 **0.001299**。

三条沉淀：

1. **warmup 的两半必须分开验**：它管的是「早期大 lr 把权重推坏」（hot 组峰值 **12.6887 → 4.3257**，压低 **8.36**），不管「后期收敛」（hot 组终值 3.28–3.36，一动不动；同模型 lr=1e-3 是 1.61）。稳值档上跑三档看不到任何差别，那**不能**证明「warmup 有用」，只能证明「这一档不需要它」。
2. **一句正确的结论，也需要一次能证伪的实验**：判据原文只要求 base 三档，但「warmup 解决早期推坏」这句话在 base 组等于没被测过 ⇒ 追加 hot 组（同一模型、只换 lr）把机制量出来。这是「判据要能红」的一次实战。
3. **耗时不可跨批比**：同一天同一脚本，关 1 单档 34–38 s，关 2 单档 70–74 s（同 lr、同步数、同显存 0.368 GiB）⇒ 机器热状态/后台负载能整倍改变耗时。

## 关卡 3（过拟合 · 同日完成）

语料 `text[:100_000]` ⇒ train 90,000 / val 10,000 · 词表 **61**（全量是 65）。

| 项 | 基线 wd=0.01 | 干预 wd=0.1 |
|---|---|---|
| 到 train CE < 0.5 | **1500** 步 | **1700** 步（+200） |
| 拐点 | step **700** · val **1.6689** | step **700** · val **1.6586** |
| 末步 | step 3500 · val **4.6881** | step 3700 · val **4.4441** |
| 升幅 / 上升次数 | **+3.0192** / 26 次 | +2.7855 / 28 次 |
| 末步 gap | **4.5064** | 4.2582 |

**结论**：wd 0.1 **有效但很弱** —— 把「背下来」拖慢 13.3%、把上限压低 0.24，**没阻止过拟合**（val 仍然升到 4.44，比随机初始化 4.21 还差）。真正的解法是**早停**（step 700 就停，val 1.67）或更多数据，不是加 wd。

两条沉淀：

1. **过拟合是「被噪声盖住」而不是「不存在」**：1.1 MB + 2000 步那组，末段 val 从 1.7974 升到 1.7983（+0.0009），远小于噪声带 0.0196 ⇒ 看不见。100 KB 把「每参数分到的字符」从 1.21 压到 0.11，现象才升到可测量级（末步比拐点高 **3.02**）。
2. **「训到某个 train CE」比「固定步数」更危险**：固定 2000 步时停在一个还算体面的点；一旦按 train CE 停（判据要求 <0.5），实际停在 **1500 步**，而那时 val 已经从 1.67 爬到 2.9 上下 —— **训练指标达标的时刻，往往已经错过最优模型几个百步**。

## 关卡 4（batch · 同日完成）

锚点写死 = 关 1 实测最优（batch 64 + lr 1e-3）⇒ `lr(b) = 1e-3 * b / 64`。

| batch | lr | 终值 val CE | ms/步 | 峰值 GiB | 该档 token 数 |
|---|---|---|---|---|---|
| 8 | 1.25e-4 | 2.384780 | 16.9 | 0.135 | 2.05 M |
| 32 | 5e-4 | 1.733131 | 16.3 | 0.222 | 8.19 M |
| 128 | 2e-3 | **1.587324** | 28.8 | 0.664 | **32.8 M** |

同 lr 1e-3 只换 batch：batch 8 → **1.838578**（比缩放组好 **0.546**）；batch 128 → **1.593847**（比缩放组差 **0.0065**）。

三条沉淀：

1. **小 batch 对 lr 极敏感、大 batch 不敏感**：batch 8 把 lr 提到 8 倍改善 0.546（说明线性缩放给小 batch 的 lr 偏小、2000 步没走到位）；batch 128 砍一半 lr 只差 0.0065。
2. **「各 2000 步」≠ 等量数据**：每步 token 数差 16 倍 ⇒ batch 128 的 1.5873 里混着「多看了 30 M token」。判据没要求等 token，但结论必须带这句；补测（batch 8 跑 16000 步）未做。
3. **batch 越大显存越贵**：0.135 → 0.222 → 0.664 GiB（batch 128 是 batch 8 的 **4.9 倍**），而每步耗时只涨 **1.7 倍** ⇒ 大 batch 是「拿显存换吞吐」。
